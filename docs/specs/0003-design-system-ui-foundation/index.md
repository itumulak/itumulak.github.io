# 0003. Design system and UI foundation

**Date**: 2026-07-26
**Status**: Proposed

## Summary

This decision fixes how the site's visual language and 13 ported components (Menu, Avatar, Headline, Timeline, Card, Socials, Pill, Reveal, Tags, Container, Section, LayoutHeader, SubHeadline; the orphaned `Modal` is dropped) work in Astro. Tailwind carries every component's styling, including Avatar (MUI is not carried into any ported component, see Rationale). Each component ships as static markup with just its animated or interactive fragment hydrated as a small React island, instead of the whole component; because the shared `Reveal` animation is used by 8 of the 13 components, this reduces how much of each page's DOM needs React, not how often Framer Motion loads on a page. It also fixes the shared design tokens (brand color, type, spacing, breakpoints, all carried over from the existing brand), and folds in concrete accessibility fixes the legacy code never had (keyboard/focus handling on the menu, a screen reader reachable alternative to hover only tooltips).

## Requirements

Not applicable. This is a decision only spec (architecture mode): it records the chosen design system, not a build plan. The work that applies this decision (scaffolding the shared tokens, porting each component) is executed by `/develop` under scope feature 4 ("Design system & UI foundation"), which derives its own build steps from `## Proposed stack` below.

## Decision

**Chosen option**: Option 1: Tailwind primary hybrid, surgical islands, reused animation primitive, accessibility fixed now

Tailwind utility classes carry all layout, spacing, and typography, for every ported component including Avatar; no CSS in JS layer (`styled-components` stays dropped, matching the already updated `package.json`), and MUI is not carried into any ported component (see Rationale, this narrows from the original plan to keep MUI on Avatar). Every component ships as static Astro markup by default; only the specific animated or interactive fragment hydrates as a small React island (`client:visible`). `Reveal` (the legacy scroll animation primitive 8 of the other 13 components depend on) is kept as the one shared animation island, with a fixed prop shape and a single nesting rule (below) so composing it stays predictable; `Avatar` is refactored to compose it instead of duplicating its own scroll animation logic. The menu's real accessibility gaps (no `aria-expanded`, no focus trap, no Escape handling) and the tag list's hover only tooltip are fixed as part of this port, not deferred, with a concrete implementation named for each.

**Implementation skills**: `mui` (`softaworks/agent-toolkit`, `.agents/skills/mui/`) · `tailwind-4-docs` (`lombiq/tailwind-agent-skills`, `.agents/skills/tailwind-4-docs/`)

## Rationale

See `rationale.md`. One change from the original design conversation, made during this spec's cross check: MUI is dropped from `Avatar` too (not just `Modal`), because an MUI `Avatar` is a React component and would need its own Emotion styles extracted at build time, which Astro's static output does not wire up for an unhydrated `.astro` shell; making `Avatar` an island just to keep one `sx` prop's worth of MUI styling was not worth the extra JavaScript. Plain Tailwind classes on an `<Image>`/`<img>` element cover the same sizing and border treatment with no island needed. This means MUI has no consumer left in the ported component set (`rationale.md` records the full reasoning); see Follow up.

## Proposed stack

| Layer | Choice | Reason |
|---|---|---|
| Styling, primary | Tailwind CSS v4 utility classes for all layout, spacing, typography, on every ported component including Avatar | Already the majority approach in the legacy code and the project's chosen styling tool; one system instead of the legacy mix of four |
| Component library scope | MUI not used by any ported component (`Modal` dropped as orphaned; `Avatar` moved off MUI during this spec's cross check, see Rationale) | Keeping MUI's footprint at zero for this component set avoids an island that exists only to carry one `sx` prop's worth of styling; see Follow up on whether MUI stays a project dependency at all |
| CSS in JS | None | `styled-components` is already absent from the new project's `package.json`; this spec makes that already made call explicit and permanent, so no later feature reintroduces it |
| Design tokens | Tailwind v4 `@theme` block in one global stylesheet (`app/src/styles/global.css`), carrying over the legacy `:root` variables as named tokens: `--color-brand: #0aff9d; --color-bg: #282c34; --color-text: #ebecf3; --font-sans: "Poppins Variable", ui-sans-serif, system-ui, sans-serif;`. `body { background: var(--color-bg); color: var(--color-text); font-family: var(--font-sans); }` goes in an `@layer base` block, not repeated per page. No custom spacing or type scale, Tailwind's defaults apply | `@theme` is Tailwind v4's convention for tokens that should generate utilities/variants (per the `tailwind-4-docs` skill); carrying the existing brand forward as named tokens (not just hex literals) means every future utility (`bg-brand`, `text-brand`) reads from one source, and zero visual regression from the live site |
| Stylesheet layer order | `global.css` declares `@layer mui, theme, base, components, utilities;` at the top, before importing `@fontsource-variable/poppins` and Tailwind itself | An explicit layer order is required for predictable cascade once more than one layer contributes rules (Tailwind's own layers plus the third party Timeline CSS below); without stating the order, later layers win by load order instead of intent |
| Breakpoints | Tailwind v4 defaults (`sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px), no custom scale | Already exactly what the legacy code uses everywhere, including `Headline`'s hand rolled duplicate of the same values; this retires that duplicate |
| Typography | Poppins, self hosted via `@fontsource-variable/poppins` (new dependency), referenced as `--font-sans` in the `@theme` block | Removes the legacy Google Fonts CDN request entirely (no external font host, no third party network dependency); one variable weight file covers every weight the legacy CSS defines |
| Animation primitive | Framer Motion (already a dependency), scoped to a fixed set of islands: `Reveal`, `Menu`, `Socials`, `Timeline`. Simple hover/focus micro interactions (e.g. Card's link icon hover) use plain Tailwind `hover:`/`transition` utilities instead | A hover scale needs no JavaScript at all in pure CSS; reserving Framer Motion for genuinely orchestrated animation (scroll reveal, staggered mount, slide) keeps its use limited to where it earns it. Note this bounds *which components* use Framer Motion, not how many pages load it: `Reveal` is used by 8 of 13 components, so most real pages still load the Framer Motion chunk once, via whichever `Reveal` instance hydrates first |
| Reduced motion | Each animated island calls Framer Motion's `useReducedMotion()` itself and passes the result into its own `animate`/`variants` | Astro islands hydrate independently; there is no single shared React tree to wrap in one `MotionConfig`, so the check has to live per island, not as one global provider |
| Hydration directive | `client:visible` as the default for every interactive or animated island, except `Reveal` itself uses `client:visible={{ rootMargin: "200px" }}` | A plain `client:visible` on `Reveal` is self defeating: its hydration trigger and its scroll reveal trigger would be the same event, so it would already be on screen once it hydrates. A `200px` root margin hydrates it slightly before it scrolls into view, so the reveal animation still has room to play. `Menu`/`Socials` (visible on load) and `Timeline` (a large below the fold block) keep the plain default |
| Island granularity | Surgical: a static `.astro` shell per component, with only the animated or interactive fragment as a nested React island, unless the animated fragment is more than roughly 70% of the component's own markup, in which case the whole component is one small island (this is why `Socials` and `Menu` are each one island, not a shell plus a nested fragment) | Most components' markup (text, layout, links) never needs React; only the fragment that actually animates or handles input does. The 70% threshold is stated explicitly so a future component's boundary is a repeatable call, not a one off judgment |
| `Reveal` prop shape and nesting rule | `interface RevealProps { children: ReactNode; delay?: number /* default 0 */; y?: number /* default 24, px */; once?: boolean /* default true */; amount?: number /* default 0.2, viewport fraction */ }`. At most one `Reveal` wraps a given subtree; a component that needs staggered children (e.g. Tags' label row and tag row) sequences them with `delay` on siblings, never by nesting one `Reveal` inside another | A nested `Reveal` (parent wrapping a child that is itself wrapped) would double fade/race on the same viewport entry; fixing the prop shape and the one level rule now means every component composing `Reveal` (`Avatar`, `Card`, `Headline`, `Pill`, `SubHeadline`, `Tags`, `Timeline`) does it the same way |
| `Reveal` initial render (no flash of hidden or wrong content) | Server rendered markup starts visible (no `opacity: 0` in the initial HTML); on hydration, `Reveal` only starts its hidden to visible transition if the element is still below the viewport at that moment, otherwise it renders as already shown, no transition plays | With JavaScript disabled or slow to hydrate, content must not be stuck invisible; and content already on screen at hydration time must not visibly flash hidden then fade back in |
| Timeline library | Keep `react-vertical-timeline-component` (already a dependency), rendered as one whole island; its bundled stylesheet is imported once in `global.css` as `@import "react-vertical-timeline-component/style.min.css" layer(components);` | Already installed at no extra cost; it is itself a React component tree, so it cannot be split into a static shell plus a smaller island. Importing its CSS into the `components` layer (per the stated layer order above) means Tailwind's own base and utility layers still override it predictably instead of an unscoped stylesheet fighting Tailwind's cascade by load order |
| Icon library | `react-icons` (already a dependency), used uniformly for every icon (menu, socials, tags, card links) | Already the pattern in the legacy code for most icons; one library instead of a mix of a component library and raw SVG files |
| Directory | `app/src/components/`, one file per component; `.astro` for a static shell, `.tsx` for an island (matches `AGENTS.md`'s existing file type rule) | A dedicated shared UI folder at the same level as `app/src/features/`, since these components are used across every future page/feature, not owned by one; this narrows `AGENTS.md`'s current folder by feature rule for shared UI specifically, see Follow up |
| Assets | Photos and thumbnails in `src/assets/`, read through Astro's `<Image>` component; fixed URL static files (the resume PDF, e.g. `public/ian-tumulak-resume.pdf`) in `public/` | Astro's standard split: `<Image>` gives automatic resizing/format/lazy loading for photos; a file that must be served byte for byte at a fixed URL bypasses that pipeline by design |
| Accessibility baseline | Fixed as part of this port. `Menu`: the hamburger toggle gets `aria-expanded` (reflecting open state) and `aria-controls` (pointing at the panel's id); the open mobile panel traps focus (a small `useFocusTrap` hook cycling `Tab`/`Shift+Tab` among its focusable children), moves focus to its first link on open, restores focus to the toggle button on close, closes on `Escape`, and the page `<body>` gets `overflow: hidden` while it is open. `Tags`: drop the hover only native `title`; each tag keeps its short visible label and adds a `<span class="sr-only">{full name}</span>` for its accessible name, no separate tooltip mechanism, no extra JavaScript | `AGENTS.md` sets a WCAG AA baseline for ported UI; every later page built on these components should start compliant, not inherit already documented gaps, and each fix needs a concrete implementation, not just a named goal, so `/develop` isn't the one deciding how |

**Component treatment** (file type and animation strategy per ported component; `Modal` dropped, not listed):

| Component | File(s) | Animated/interactive fragment |
|---|---|---|
| Reveal | `Reveal.tsx` (island, `client:visible={{ rootMargin: "200px" }}`) | Is the primitive itself: scroll in view fade/slide per the prop shape and initial render rule above, `useReducedMotion()` aware |
| Avatar | `Avatar.astro` shell (plain `<Image>`/`<img>` sized and bordered with Tailwind, no MUI), composes `Reveal.tsx` | Refactored to reuse `Reveal` instead of its own bespoke scroll animation; MUI dropped here too (see Rationale) |
| Menu | `Menu.tsx` (full island, `client:visible`) | Fully stateful (open/close, scroll nav); implements the accessibility baseline above |
| Socials | `Socials.tsx` (full island, `client:visible`; qualifies for the "whole component" case, its animated fragment is nearly all of its markup) | Mount stagger plus hover |
| Card | `Card.astro` shell, one nested `Reveal.tsx` wrapping the stack/summary block, plain Tailwind `hover:`/`transition` for the link icon scale | Only the reveal fragment needs React; the hover effect is pure CSS; no second, nested `Reveal` |
| Headline, Pill, SubHeadline | `.astro` shell each, one nested `Reveal.tsx` | Static content wrapped by the shared animation island |
| Tags | `Tags.astro` shell, one `Reveal.tsx` wrapping the whole tag list (not two separate instances); the sr-only accessible label above, no tooltip | One `Reveal` per subtree per the nesting rule; label row and tag row stagger via `delay`, not via a second `Reveal` |
| Timeline | `Timeline.tsx` (full island, `client:visible`); its CSS imported once in `global.css`, see above | Third party library is itself a React tree; not splittable |
| Container, Section, LayoutHeader | `.astro`, no island | Purely static; `LayoutHeader` composes the `Menu`/`Socials` islands as children |

**New base layout**: an Astro root layout (`app/src/layouts/Layout.astro`) imports the global stylesheet (tokens, layer order, `@fontsource-variable/poppins`) and wraps every page; nothing like it exists yet on the Astro side.

## Consequences

**Positive**:
- Every component's own layout/text markup ships zero JavaScript; only the fragment that actually animates or handles input becomes an island, and each island's boundary follows a stated, repeatable rule (the 70% threshold, the nesting rule) instead of a one off judgment per component.
- One canonical scroll animation implementation (`Reveal`) instead of two (Avatar's bespoke copy retired), with a fixed prop shape so every component composing it does it the same way.
- Every page built on this foundation starts WCAG AA compliant on the menu and tag components, with a concrete implementation named for each fix, instead of inheriting documented gaps or a vague goal `/develop` has to interpret.
- Self hosted Poppins removes an external network request the legacy site made on every page load.
- Dropping MUI entirely from the ported component set removes a class of build risk (Emotion styles not extracting from an unhydrated shell) before it ever surfaces.

**Negative / tradeoffs**:
- Because `Reveal` is used by 8 of the 13 components, most real pages still load the Framer Motion chunk once (via whichever `Reveal` instance hydrates first); the JavaScript savings here are in avoiding whole component hydration and unnecessary React elsewhere, not in avoiding Framer Motion itself. A from scratch, non React `Reveal` (IntersectionObserver plus CSS transitions) would cut Framer Motion further; this spec keeps the proven primitive instead, see Follow up.
- Per component island boundaries are more design and engineering judgment up front than a blanket "port as is, whole component island" pass, even with a stated threshold.
- The accessibility fixes (focus trap, Escape handling, the sr-only tag label) are new code, not a straight port, and need their own verification that the interaction still feels right.
- MUI now has no consumer anywhere in the ported component set, which raises a question this spec does not resolve: whether MUI stays a project dependency at all (see Follow up).

**Neutral**:
- `styled-components` and the hand rolled breakpoint helper in `Headline` are retired; any future component must use Tailwind, not reintroduce a CSS in JS layer or MUI.
- `@fontsource-variable/poppins` is a new dependency; declined an Agent Skill/MCP search for it (a static font asset package, no real conventions to teach an agent).

## Follow-up

- [ ] MUI (and `@emotion/*`) now has zero consumers in the ported component set (`Modal` dropped, `Avatar` moved off it during this spec's cross check). Spec 0001 chose MUI as a project dependency; reconsider there, or in a future spec, whether it stays installed for a later feature, or gets dropped, rather than carrying an unused dependency forward by default.
- [ ] `app/src/components/` (this spec's directory choice for shared UI) narrows root `AGENTS.md`'s current "folder by feature" rule for shared UI specifically. `AGENTS.md` should record this carve out explicitly (`/sync`'s job) so a future feature doesn't read the folder by feature rule as forbidding a shared components folder.
- [ ] If Framer Motion's bundle weight becomes a real, measured concern once the site is built, reconsider replacing `Reveal`'s Framer Motion implementation with a native `IntersectionObserver` plus CSS transitions version (no React at runtime for scroll reveals); this spec chose the proven, already installed primitive over that rebuild for a one engineer project, not because the rebuild has no merit.
